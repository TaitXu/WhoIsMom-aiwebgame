# 《小蝌蚪找妈妈》4 页项目介绍 Deck · 方向稿设计 Spec

## 项目与目标

《小蝌蚪找妈妈 / Who is Mom》是一款 AI 原生的实时小队管理、冒险解谜与轻推理游戏。玩家扮演领路小鱼，带领三只性格不同、记忆容量有限的小蝌蚪穿过九区域水乡。玩家无法直接听见 NPC 的原始证词，只能通过分派调查、查看二手记忆、安排同伴对证与复查，判断三只候选青蛙中谁才是真正的妈妈。此次 deck 用于在约 3-5 分钟内向游戏开发者、评委、合作伙伴或对 AI 游戏感兴趣的听众讲清：这个项目不是“让 AI 生成对白”，而是把 Agent 的认知上下文、性格偏差、疲劳与有限记忆变成玩家需要管理的核心资源。

## 四页叙事结构

1. **项目钩子**：游戏类型、童话背景与一句话体验。核心句为“你管理的不是单位，而是一群不完整的认知者”。
2. **小队与性格**：墨点（谨慎、复述准确但易退缩）、小浪（冲动、行动快但会省略语境）、泡泡（亲和、善追问但容易被同伴影响）。AI 同时生成本局蝌蚪性格表达与候选青蛙外观，但世界真相仍由确定性规则控制。
3. **记忆机制**：新信息进入有限的 3-5 个记忆槽；记忆会更新、强化、覆写与遗忘。反馈受性格、现有记忆、疲劳度、交谈对象、信息来源与同伴交流影响。玩家真正管理的是“谁在什么状态下，从谁那里记住了什么”。
4. **核心循环**：移动与探索地图 → 分配蝌蚪调查或清障 → 与 NPC 交流 → 查看记忆变化 → 安排蝌蚪对证/复查 → 更新妈妈画像 → 找候选青蛙对证与决断 → 结算复盘信息传播链。

## 受众、场景与情绪

受众默认是能理解游戏机制与 AI Agent 概念，但未读过完整策划案的听众；观看距离按 5-10 米投屏处理。正文不低于 28px，标题 72-160px，单页只保留一个主结论。情绪需要同时具备童话的温暖、调查推理的清晰，以及 AI 认知系统的“轻微不可靠感”。不能做成通用科技蓝紫、后台 Dashboard 或儿童绘本；它首先是一款可玩的游戏，其次才是一项 AI 技术实验。

## 输出与资产

方向稿为三套视觉方向，每套 2 张 1920×1080 HTML 代表页：封面页 + 记忆机制页。三套共用项目真实截图 `game-start.png`、`game-scene.png`、`memory-panel.png`，以及仓库字体 `HuiWenMingChao.ttf`。用户选定方向后，再按同一视觉 grammar 完成 4 页 HTML deck、聚合演示页与 PDF。当前阶段不为可编辑 PPTX 的 html2pptx 限制牺牲视觉；如后续明确需要可编辑 PPTX，再制作兼容衍生版。

## Form 推导五问

- **叙事角色**：封面是 hero；机制页是解释与证据页。
- **观众距离**：以投屏为主，远距离先读结论，再近看机制细节。
- **视觉温度**：温暖童话 60%，冷静推理 25%，轻微认知不安 15%。
- **容量估算**：每页最多一个主句、一个主图或主结构、三到六个短标签；完整细节留给讲述。
- **视觉母题**：水波中的记忆痕迹。记忆不是静态数据库，而是会被新波纹改写、互相干扰、逐渐淡去的水痕；这个母题只属于“沿河寻找妈妈 + 有限 Agent 记忆”的内容。

## 三个方向

1. **田野调查手册**：秒数轮盘结果 18，对应 Humanist Rounded Cards。沿用游戏奶油纸、墨绿、胶带、手写调查笔记与现有明朝体，可信、温暖、接近游戏实机。
2. **Direct 玩法发布**：现实参照为 Nintendo Direct / Indie World 的大标题、高饱和色块和“先看玩法动词”的发布节奏。结构比 A 更舞台化、更适合现场 pitch。
3. **记忆水痕**：以原研哉式留白与东方编辑设计为思想锚点。用覆写文字、水波、淡墨证据链表现认知的不稳定，强调项目的独特概念与作者性。
